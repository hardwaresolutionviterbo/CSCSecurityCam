# Identità approvate per 01-verifica.sh (esempio).
#
# Copia questo file come identita-approvate.txt nella stessa cartella (non va su GitHub: è
# escluso da .gitignore perché può contenere email) e lascia SOLO le righe che hai controllato.
#
# Senza questo file nessuna identità è approvata: ogni identità diversa da te che, nel progetto o
# sopra, può impersonare firestore-audit, crearne o caricarne chiavi, eliminarlo e ricrearlo,
# cambiarne i permessi o modificare il ruolo personalizzato fa fallire la verifica.
#
# Una riga per membro IAM, scritto esattamente come in IAM. Il testo dopo # viene ignorato.
#
# Si possono approvare SOLO:
#   user:EMAIL                 una persona. Se ha privilegi pericolosi l'esito resta comunque
#                              INCOMPLETO (mai positivo): lo script non può verificare chi usa
#                              il suo account. L'approvazione evita solo il PROBLEMA.
#   serviceAccount:EMAIL       un account di servizio di QUESTO progetto che esiste
#                              (...@nexus-social-e3eee.iam.gserviceaccount.com,
#                              nexus-social-e3eee@appspot.gserviceaccount.com,
#                              NUMERO-compute@developer.gserviceaccount.com). Lo script controlla
#                              anche chi può impersonarlo e se ha chiavi.
#   serviceAccount:EMAIL       un agente Google di QUESTO progetto, per indirizzo esatto:
#                              service-NUMERO@gcp-sa-SERVIZIO.iam.gserviceaccount.com,
#                              NUMERO@cloudservices.gserviceaccount.com e pochi domini storici
#                              (NUMERO = numero del progetto). Controlla prima i suoi ruoli.
#
# NON si possono approvare (la riga viene rifiutata e la verifica dà PROBLEMA): gruppi, domini,
# identità federate (principal, principalSet), allUsers, allAuthenticatedUsers, membri eliminati,
# account di altri progetti, account del dominio condiviso firebase-sa-management.
# La vecchia riga "agenti-google-del-progetto" non approva più nulla.
#
# Esempi (da adattare):
# serviceAccount:service-NUMERO@gcp-sa-firebase.iam.gserviceaccount.com
# serviceAccount:NUMERO@cloudservices.gserviceaccount.com
# serviceAccount:firebase-adminsdk-xxxxx@nexus-social-e3eee.iam.gserviceaccount.com
# user:collaboratore@example.com
